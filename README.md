# 夜班接驳车工具：末班核定 + 到站实到核对

给夜班通勤协调员 / 运营值班员用的 Web 工具，含两个功能：

1. **末班核定**（`/`）：输入时刻表首页 URL、上车站、下车站、最早出门与
   到岗截止的日期时间，自动翻页抓取两站时刻表，按**车次号 + 停站顺序**配对，
   只保留“发车不早于出门、到站不晚于截止”的班次，给出**发车最晚的一班**及两站来源。
2. **到站实到核对**（`/verify`）：输入时刻表首页 URL、实录首页 URL、上车站、
   下车站和实际到站日期，分别抓齐两边分页，按两站停站顺序与始发服务日**还原
   计划到站时刻**，与实录（仅车次号 + 实际到站日期时间）做**一对一配对**，
   找出可确认的晚点班次供车队查因。

## 实到核对规则

- **计划还原**：两站记录车次号相同、上车站停站顺序早于下车站才视为同一行程；
  计划到站时刻 = 始发服务日零点 + 下车站时刻（`24:25`、`25:10` 等跨日写法自动
  换算；`01:00` 等 00:xx 写法若早于上车站发车，按次日处理，与 24:xx 写法等价）。
- **配对窗口**：实到允许比计划**早 15 分钟至晚 120 分钟**，按车次号 + 时间
  一对一配对——某条实录与某个计划互为唯一候选才算**确定配对**。
- **待核实**：相邻服务日的同号班次（如周五深夜与周六凌晨各一班）或其他原因
  造成多种配对可能时，整组标记**待核实**并列出全部候选，**不按页面顺序任选一条**。
- **展示**：确定配对列出计划到站、实到时间、晚点分钟（提前为负）与两侧来源
  分页；另列出未见实到的计划班次（可能缺车）、无匹配计划的实录记录，以及
  无法还原计划的车次告警。
- **缺页保护**：时刻表或实录任一来源缺页 / 抓取失败时，**只展示已抓取记录与
  失败页，不下晚点或缺车结论**。

## 功能要点（末班核定）

- **分页抓取**：从首页的站点链接（`a.station-link`）找到两站第 1 页，沿
  `a.next-page` 逐页抓取，直到没有下一页（50 页上限、循环链接保护）。
- **服务日区分**：按车次**始发服务日**标注工作日（周一至周五）/ 周末（周六周日）/
  每日；查询时按时间窗覆盖的每个始发日分别判断是否运行。
- **异常提示**：
  - 任一分页抓取失败 / 表头缺列 / 链接循环 → 提示“无法核定末班”，且不展示不可信结论；
  - 车次缺停站顺序、缺关键时刻、两站服务日标注不一致、下车站无该车次记录 →
    逐条告警；若仍有其他完整班次，正常给出末班，告警与答案同时展示。

## 目录结构

```
.
├── app/                  # Flask 应用（端口 5000）
│   ├── commuter/
│   │   ├── times.py      # 纯逻辑：时刻解析、服务日、末班配对（可单测）
│   │   ├── verify.py     # 纯逻辑：计划到站还原 + 实到一对一配对（可单测）
│   │   ├── scraper.py    # requests + BeautifulSoup 分页抓取（时刻表 + 实录）
│   │   ├── app.py        # Flask 路由：/ 末班核定、/verify 实到核对
│   │   └── templates/    # index.html、verify.html
│   ├── tests/            # 单元测试 + 端到端冒烟测试
│   ├── Dockerfile
│   └── requirements.txt
├── example-site/         # 本地示例时刻网站（端口 5001）
│   ├── app.py            # 分页时刻表 + 分页到站实录；含 24:xx 跨日、工作日/周末、
│   │                     # 相邻服务日同号班次、缺记录车次与 500 故障分页
│   ├── Dockerfile
│   └── requirements.txt
└── docker-compose.yml
```

## 用 Docker Compose 启动（推荐）

```bash
docker compose up --build
```

- 示例时刻网站：<http://localhost:5001/>
- 核定 / 核对应用：<http://localhost:8000/>（实到核对在 <http://localhost:8000/verify>）

| 字段 | 示例值 |
| --- | --- |

| 下车站 | `中央厂区` |
| 最早出门 | `2026-11-11 22:00` |

## 本地直接运行（不用 Docker）

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r app/requirements.txt

# 终端 1：示例时刻网站
cd example-site && python app.py            # http://localhost:5001

# 终端 2：核定应用
cd app && flask --app commuter.app run      # http://localhost:5000
```

此时首页 URL 填 `http://127.0.0.1:5001/`，实录首页 URL 填
`http://127.0.0.1:5001/log/`。

## 试一下演示场景（实到核对）

示例实录覆盖 2026-11-12 / 11-14 / 11-15 三个到站日期：

- **2026-11-12**（常规夜）：N201 / N202 / N203 / N205 / N210 确定配对
  （含 24:xx / 25:xx 跨日计划、晚点 70 分钟、提前 10 分钟）；N207 未见实到；
  X999 无匹配计划；N206 缺下车站记录仅告警。
- **2026-11-14**（相邻服务日同号）：N210 同时存在「工作日 25:35」（周五始发，
  计划 01:35）与「周末 01:30」（周六始发，计划 01:30）两个计划，实录 01:40
  与两者都可配对 → 整组**待核实**，不会按页面顺序任选一条。
- **2026-11-15**（00:xx 跨日写法）：N204 下车站时刻写作 `01:00`（未用 25:00），
  自动按次日还原，实到 02:40 判定晚点 100 分钟。
- **实录缺页**：实录首页 URL 改填 `http://example-site:5001/log-broken/`，
  其第 2 页返回 500，页面只展示已抓取的时刻表 / 实录记录与失败页地址，
  不下晚点或缺车结论。
- **时刻表缺页**：上车站填「故障北站」，其第 2 页返回 500，同样只展示
  已抓取记录与失败页。

## 试一下异常场景（末班核定）

- **缺记录**：示例数据里 N206 在「中央厂区」没有停站记录，任意
  滨河园区→中央厂区查询都会看到黄色数据告警，末班仍由 N205 等完整数据核定。
- **分页失败**：上车站填「故障北站」，其第 2 页返回 HTTP 500，页面显示红色
  “无法核定末班”，并标明失败的分页地址。
- **周末 vs 工作日**：把时间窗放到周六晚上（如 2026-11-14 22:00 至
  2026-11-15 02:00），结果中只会出现“每日”和“周末”班次。

## 适配真实时刻表 / 实录站点

抓取器对页面结构的约定（见 `app/commuter/scraper.py`）：

1. 时刻表首页上站点链接带 `class="station-link"`，文本为站点名；
2. 站点页有 `<table>`，表头包含 车次号 / 停站顺序 / 站点 / 时刻 / 服务日
   （支持常见别名，如“站序”“班车”“到时”等，见 `_HEADER_ALIASES`）；
3. 实录首页 URL 即实录表格第 1 页，表头包含 车次号 / 实际到站时间
   （别名见 `_LOG_HEADER_ALIASES`），每行只有车次号与实际到站日期时间；
4. 两种页面的翻页链接都带 `class="next-page"`；
5. 服务日列出现“工作日/平日/weekday”“周末/双休/weekend”“每日/daily”等字样。

结构不同的站点只需调整 `scraper.py` 中的选择器与表头别名，核心核定 / 核对
逻辑（`times.py`、`verify.py`）无需改动。
